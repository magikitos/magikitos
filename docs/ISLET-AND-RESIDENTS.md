# Island and resident library

Local implementation, September 2026. The public website and its API boundary are
unchanged. No deployment or save reset is part of this work.

## Play and scenery

- No opening dialogue. A new player can explore immediately.
- Walking resumes camera following after a manual map pan. Following is clamped
  at map edges, so centring never reveals an empty strip outside the scene.
- A pickup's source disappears as the overhead presentation begins, not after
  it finishes. Its inventory transaction still commits atomically at the end.
  Reloading/cancelling an unfinished sequence cannot lose the object or grant it
  twice. Reusable gathering plants and work stations do not disappear.
- The separate picnic basket, picnic pond and stream are removed. The picnic,
  its animation and utensils remain; existing completion still makes the humans
  leave. The boat lake and crossing are preserved.
- The existing island now has three enterable houses, vegetable beds, a seedling
  table, branch fences, flower arch, hammock and inhabited footpaths. New dialogue
  is available in all six languages. No new quest mechanics were added; existing
  skewer, fare and shell-collector rules are unchanged.

## 100 residents, not 100 simultaneously downloaded actors

The cast contains **20 design families × 5 independently drawn variants**:
100 unique source sheets, evenly split between male and female profiles, with
different ages, builds, natural skin tones, faces, clothes and pointed hats.
Families group related designs for the Studio; variants are not runtime recolours.

- Canonical identities, descriptions and prompts:
  `data/aventura/art/residents/catalog.json`.
- Original sheets and alpha-only derivatives: `residents/sources/` and
  `residents/cutouts/`.
- Runtime metadata: `data/aventura/residents.json`, generated by
  `npm run art:catalog`. It excludes prompts and source details.
- Each ID 100–199 owns an independent `actor-<id>` pack with 32 poses:
  eight directions × idle plus three walking steps. Registration is shared across
  the sheet: 48×48 logical canvas, feet at [24,46], approximately 40px body height.
- The accepted **2× integrated reduction** remains in use. Original large sheets
  never ship to players and there is no runtime alpha extraction.
- `ZoneCasting` gives an identity a deterministic preference and resolves local
  collisions without repeating a whole design family in the same zone. Authored
  actors reserve their families too. Exhaustion is an explicit error, not silent
  visual duplication; keep a zone within its available family count.
- Ambient wandering and animation run in the browser. They do not imply live
  presence or add server polling.

Studio derives its 20 resident families from the same runtime metadata, under
**Duendes · vecinas / vecinos**. Every family offers five explicit variants.
They use normal placement, transforms, save, undo and review, not a separate
character editor. A user-chosen variant remains stable.

### Brizno

Brizno is not an ambient variant: ID 12 has a conspicuous round belly, drooping
white moustache, spectacles, curled lilac cap and striped shirt. His seated and
walking sheets keep one identity. The bench is a separate reusable prop.
Both complete prompts are in `art/residents/brizno-prompts.json`; originals
are in `art/cast/sources/brizno-{seated,walk}.png`.

## Doors and shared interiors

All open house families declare `entrance: "open"` in the canonical
`element-families.json`. Their templates contain an actual portal and travel
effect. Compilation rejects an open building without an entrance.

Four reviewed mushroom/pot doorway editions replace visibly closed doors with
open entrances. Their immutable masters, exact edit prompts and alpha reports
live in `art/doorways/`. The artwork generator reads that edition catalog;
regenerating the woodland collection cannot silently restore the closed art.
Neutral background removal is an offline, reference-assisted alpha operation;
it does not repaint the house. Original woodland masters remain untouched.

Each entry saves its source scene and portal ID. `doorDestination` resolves the
current portal coordinates on exit, including an island house using a shared
interior. Deleted entrances fall back to the authored safe destination. Door
entry still requires a deliberate upward approach, and exit a downward one.

The two new room themes are `mushroom-home` and `pot-home`, with organic floors,
natural furniture and the existing painted cutaway framing.

## Compound scenery collisions

The flower arch uses `solids`: two local rectangles, one for each post.
`collisionBodies` expands them into the same spatial index and navigation
occupancy used by ordinary bodies. The centre remains walkable. Compound bodies
are currently static scenery only; mixing them with `solid`, actors or pushable
objects is rejected. No object-specific collision branch is needed.

## Authoring and reproducibility

1. Review/generate a source sheet and record its prompt in the appropriate art
   catalog. Keep originals immutable.
2. Run the relevant preparation task:
   `npm run art:cast`, `npm run art:islet`, or `npm run art:doorways`.
   Cast registration can reference another sheet, so use the full cast task when
   changing related animation sheets.
3. Run `npm run art:catalog` to regenerate families, source editions and resident
   metadata. Edit family templates in `element-families.json`, not generated
   `elements.json`. Garden definitions use the same family blueprint.
4. Run `npm test`; it bakes content-addressed packs, builds the static artifact
   and runs the core regression suite.
5. Review `npm run studio:diff` before applying any Studio scene proposal.
   There remains one workspace, with its edit history preserved.

The runtime gallery has 3,919 sprites in 176 packages, approximately **8.9 MB of
PNG for the complete library**. That is not the initial download. Tests enforce
under 70 KB per resident pack, fewer than 25 resident packs per prepared scene,
under 4 MB of scene textures, and under 10.5 MB for the entire PNG collection.
Typical tests load roughly 2.5 MB of forest textures and 1.8 MB on the island,
depending on the local cast. Audio, JSON and bundles are separate from these
texture measurements. The existing bounded pack cache and scene pinning remain
responsible for runtime memory.
